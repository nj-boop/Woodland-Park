# Wildgrove Zoo

A 3D zoo-building and management game that runs in a web browser (desktop and phone). You lay out
paths, build habitats of any shape, shape the land, care for 18 animated species, hire staff, keep
guests happy and grow the zoo through unlock tiers.

## Quick start

```bash
npm install          # prettier (formatting) and three (used only by the tests)
npm run build        # -> dist/index.html + dist/models/*.json   (the playable game)
npm test             # builds a test version and runs the integration tests in headless Chrome
npm run format       # reformat source files
npm run models       # rebuild all animal models with Blender (slow; needs bpy)
```

`dist/index.html` must be served next to `dist/models/` (the animals load from there).

## How the code is organised

The game is plain JavaScript with no framework. `tools/build.mjs` joins the files listed in
`src/manifest.json`, **in that order**, inside one function scope, and writes a single HTML page.
Order matters: a file can use anything defined in an earlier file, and functions can be used anywhere.

| Folder | What lives there | Rule of thumb |
|---|---|---|
| `src/core/` | constants, shared state and helpers, save/load, the game loop and startup | the glue |
| `src/data/` | biomes, species, items, prices, care needs, unlock tiers, names | tables only, no logic |
| `src/sim/` | the simulation: world, guests, animals, monthly events, terrain, building rules | no drawing or DOM code |
| `src/render/` | Three.js scene, terrain mesh, ground painting, structures, foliage, animals, camera | reads game state, never changes it |
| `src/ui/` | HTML layout, styles, toolbar and panels, mouse/touch/keyboard input | turns player actions into sim calls |
| `assets/blender/` | Python scripts that build every animal in Blender (body, skeleton, coat, animations) | the art pipeline |
| `assets/models/` | the exported models the game loads | generated by `npm run models` |
| `tests/` | integration tests that drive the simulation through a test hook | run with `npm test` |
| `tools/` | build script, model conversion | |

### The main ideas

- **One state object, `S`.** Everything that gets saved lives in `S`: money, the date, the tile grid,
  terrain heights, habitats, animals, guests, staff and the hiring board. `serialize()`/`load()` in `core/save.js`
  turn it into JSON and back.
- **Derived data, `F`.** After anything changes, `rebuild()` (`sim/world.js`) recomputes facts that
  can be worked out from `S`: path distance maps for guests, which habitats a path tile can see,
  each habitat's tiles and boundary edges, staff capacity. Set `dirty = true` to request it.
- **Fixed-step simulation, smooth rendering.** `tick()` (`sim/events.js`) advances the world 20
  times per in-game second. `frame()` (`core/boot.js`) runs as many ticks as real time and game
  speed require, then renders with interpolation between ticks.
- **The grid.** The map starts at 36 × 26 tiles and can grow: `resizeMap(w, h, ox, oy)`
  (`sim/world.js`) moves the whole zoo into a bigger map, shifted by (ox, oy), and the renderer
  rebuilds everything sized to the map (`onMapResized()`). `W` and `H` are the current size. Each tile has a type (`t`: grass or path), an item (`o`),
  a habitat id (`e`), litter (`l`), a water flag (`w`) and a path material (`pm`). Terrain heights
  live on tile corners (`S.hgt`). Habitats are sets of tiles, not rectangles.
- **Buildings bigger than a tile** (`sim/footprints.js`). One tile is about 3 m. A building's size
  is `size: [width, depth]` in `ITEMS`. Every tile it covers stores the kind in `o` and its anchor
  (top-left) tile in `a`; the anchor stores the facing in `r` (0 = door faces down the map, then
  clockwise). Count buildings with `isAnchor(i)`, remove them with `clearBuilding(i)`. Models are
  in `render/buildings.js`, built facing +z and centred on the footprint. Saves store only the
  anchor and facing and re-stamp footprints on load.
- **Animals** have hunger, health, happiness and a list of reasons (`why`). `evalEncl()` works out
  each animal's target happiness from its habitat (space, plants, water, toys, shelter, company,
  predators, cleanliness, fence condition). `tickAnimals()` moves them, including hunting,
  fleeing, avoiding obstacles and escaping.
- **Staff** (`sim/staff.js`) are individual people hired from a monthly board, each with a skill
  (1–5), a trait, a wage, morale and energy. Each one picks a job (feed and clean a habitat, treat a
  sick animal, catch an escapee, sweep litter, repair a fence), walks there with `staffRoute()`
  (paths are cheapest, open ground is allowed, habitat fences can only be crossed at gates), does
  the work, and rests at their building when tired. Wages, morale changes and quitting happen at
  month end in `staffMonth()`. The staff list, hiring board and staff inspector are in
  `ui/staff-panel.js`; staff are drawn with the guest meshes, in uniform.
- **Guests** walk path tiles using the distance maps, buy from shops they pass, react to what they
  see, and leave when tired or unhappy. Their final happiness feeds the zoo rating.
- **Batching and detail by distance** (`render/batching.js`). After a chunk, fence or the outer
  forest is built, meshes sharing a geometry and material are merged into one `InstancedMesh`, so
  hundreds of trees cost a few draw calls. Chunks are hidden when off-screen and stop casting
  shadows when far away; far animals stop casting shadows and animate less often.
- **The ground** (`render/ground-splat.js`) is drawn by a shader, not painted as one picture. A
  small data texture holds one texel per tile (layer, curb and fence-edge bits, litter or dirt,
  grass-detail strength), and the shader draws each tile from a shared atlas of repeating
  textures. It works at any map size; the mesh is split into 32 × 32-tile chunks for culling.
- **Rendering** keeps static things (items, fences, tanks) in a scene graph split into 16 × 16-tile
  chunks plus one group per habitat fence (`rebuildStatic()` in `render/structures.js`). Each is
  fingerprinted, and only the ones whose fingerprint changed are rebuilt, while animals and guests are updated every frame. Guests are instanced meshes.
  Scenery uses seeded randomness so it looks the same every rebuild.

### Buying land

`sim/land.js`: the zoo grows in 16-tile strips to the north, east or west (the entrance road stays
on the south edge), up to 512 × 512. `landPrice()` rises with the zoo's area; new strips arrive as
woodland. The guest cap (`guestCap()` in `sim/guests.js`) grows with the land, up to 1,500.

### Parking

Guests come by car, about 3 to a car (`sim/guests.js`). The roadside holds 15 cars and each parking
lot (6 × 4 tiles) 30 more. When every space is taken, visitors park off-site and new arrivals drop
to a quarter (`arrivalChance()`); the Office shows cars parked and visitors turned away. Parked
cars are drawn into lot bays by `syncParkedCars()` (`render/buildings.js`).

### Keeping big maps fast

Measured on a 512 × 512 test zoo (900 habitats, 1,800 animals, 18 staff): a simulation tick takes
about 0.7 ms, placing something about 80 ms in total. Rules that keep it that way:

- Don't loop over every tile, or every animal for every animal, inside per-tick code. Use the
  lists `rebuild()` keeps: `F.paths`, `F.litter`, `F.homes`, `animalsIn(habitatId)`.
- Area effects (scenery, bins, ATMs) are stamped onto a grid around each item in `rebuild()`.
- Staff routes use A* with reused buffers (`staffRoute()`); give it small goal sets.
- Scenery, grass tufts and ground heights rebuild per chunk, only where something changed.

### Adding things

- **A new item:** add it to `ITEMS` (`data/items.js`), give it placement rules in `check()`
  (`sim/building.js`), a 3D model in `makeItem()` (`render/structures.js`) or, for a building
  with a `size`, in `BUILDINGS` (`render/buildings.js`), an icon in `IT_ICON` and a slot in the
  tray (`ui/panels.js`).
- **A new species:** add it to `SPECIES`, `CARE`, `GUIDE` and a tier in `TIERS` (`data/`), add a
  spec in `assets/blender/build_animals.py`, run `npm run models`, and list it in `MODELS`
  (`render/animals-rigged.js`). Add a fallback shape in `SPEC` (`render/animals-sculpted.js`).
- **A new rule:** put the logic in `src/sim/`, keep numbers in `src/data/`, and add a test.

## Saves

Saves go to the browser's IndexedDB (database `wildgrove`, key `wildgrove-zoo-v1`), with a copy in
local storage while the save is under 2 MB. `load()` understands older save
formats (rectangular habitats, item numbers instead of names, staff head counts instead of named
staff, habitats without gates) so updates don't wipe zoos.
